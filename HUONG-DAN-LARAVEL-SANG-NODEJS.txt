Express tự tạo. Khi gặp file HrmServiceProvider, đừng nghĩ Express tự có container
và auto-discovery như Laravel; project đăng ký handler bằng tay rất rõ ràng.

4. VÍ DỤ 1: XEM DANH SÁCH NHÂN VIÊN
====================================
Trong DJI Laravel bạn có:
  $this->queries->ask(new GetEmployeeListQuery($companyId, $filters));

Trong HRM Node bạn đọc theo thứ tự sau:

Bước 1: src/modules/employees/routes/api.js
  employeeRoutes.get(
    '/api/employees/list',
    authorize(EmployeePolicy, 'view'),
    c.list
  );

So sánh Laravel:
  Route::get('/...', [EmployeeController::class, 'index'])->middleware(...);

get() là GET. URL có /list để nói rõ thao tác, theo đúng lựa chọn của bạn.
authorize() là middleware quyền. c.list là hàm controller; truyền hàm, không gọi c.list().

Bước 2: src/modules/employees/controllers/EmployeeController.js
  data(res, await queryBus.ask(new GetEmployeeListQuery(req.query)));

So sánh:
  $request->query()             → req.query
  new GetEmployeeListQuery()   → vẫn là một object yêu cầu đọc
  $queries->ask(...)           → queryBus.ask(...)
  response()->json(...)        → data(res, ...), bên trong dùng res.json()

Bước 3: src/modules/employees/queries/EmployeeQueries.js
  GetEmployeeListQuery giữ filters.
  queryHandlers ghép Query này với repository.list(filters).

Query không phải câu SQL. Nó chỉ diễn đạt: "tôi muốn xem danh sách nhân viên
với bộ lọc này". Handler quyết định gọi repository nào.

Bước 4: src/providers/HrmServiceProvider.js
  queryBus.register(type, handler);

So sánh DJI: provider đăng ký cách xử lý một Query.
Bus tra Map theo lớp của object Query. Chưa đăng ký → lỗi wiring, không tự đoán handler.
Provider chạy một lần khi app khởi động. Không chạy lại cho từng request.

Bước 5: src/modules/employees/repositories/EmployeeReadRepository.js
  Employee.findAndCountAll({where, include, order, limit, offset});

So sánh Eloquent:
  Employee::with(['user','department'])->where(...)->paginate(10);

include tương tự eager loading bằng with().
where là điều kiện. order là sắp xếp. limit/offset là phân trang.
findAndCountAll trả rows và count; repository chuẩn hóa thành items và pagination.

Bước 6: src/modules/employees/models/Employee.js
  db.define('Employee', {...}, options('hrm_employees'));

So sánh $table = 'hrm_employees' và khai báo thuộc tính/model Eloquent.
Quan hệ belongsTo(User/Department) được nối tại src/models/index.js.
ORM vẫn đọc MySQL thật, không phải mảng giả hoặc mock.

Tóm luồng đọc:
  GET URL → Auth/CSRF pipeline → Policy → Controller
  → QueryBus → Query Handler → Read Repository → Sequelize → MySQL → JSON.

Nếu vào trang HTML /employees/list, EmployeeWebController nhận cùng Query,
đồng thời lấy options phòng ban rồi res.render('employees', ...).
Web và API dùng chung logic đọc, khác cách trình bày kết quả.

5. VÍ DỤ 2: THÊM NHÂN VIÊN
==========================
Laravel DJI:
  Controller → FormRequest → CreateEmployeeCommand → Handler/Repository
  → DB::transaction → Domain Event → Redirect/View.

Node HRM:
  POST /api/employees/create
  → authenticate
  → csrf nếu client dùng cookie
  → authorize(EmployeePolicy, 'create')
  → EmployeeController.create
  → commandBus.dispatch(new CreateEmployeeCommand(req.user, req.body))
  → EmployeeCommands.js xử lý
  → employeeSchema.parse(input)
  → transaction tạo User + Employee + audit + outbox
  → commit
  → publish event, invalidate cache, phát Socket.IO
  → JSON status 201.

Mở 4 file theo thứ tự:
  src/modules/employees/controllers/EmployeeController.js
  src/modules/employees/commands/EmployeeCommands.js
  src/modules/employees/requests/EmployeeRequest.js
  src/modules/employees/models/Employee.js

Command là "hãy làm việc này", khác Query là "cho tôi xem dữ liệu".
CreateEmployeeCommand mang actor và input, không tự chạy SQL trong constructor.
Handler của Command mới thực hiện nghiệp vụ.

Object.freeze(this) giúp không gán lại các thuộc tính của DTO ở lớp ngoài.
Đây là shallow freeze, không phải cơ chế readonly sâu hoặc một hệ thống bảo mật.
Không log Command đăng nhập/tạo account vì input có password.

FormRequest:
  Laravel: $request->validated()
  Node:    employeeSchema.parse(input)

Ở HRM này, Request schema kiểm tra name,
email, password, code, departmentId, position, joinedOn, salary, role và status.
Sai dữ liệu ném ZodError; error middleware đổi thành 422.

Một số tên field khác DJI:
  DJI employee_code    → Node Employee.code
  DJI full_name        → Node User.name
  DJI work_email       → Node User.email trong cấu trúc HRM hiện tại
  DJI join_date        → Node Employee.joinedOn
  DJI employment_status→ Node Employee.status (active/inactive)

Không đổi tên field chỉ để giống PHP rồi làm lệch migration hiện có.
Trong DB, underscored mapping đổi userId thành user_id, joinedOn thành joined_on.

Transaction:
  Laravel: DB::transaction(function () { ... });
  Node:    await db.transaction(async transaction => { ... });

Mỗi create/update cần tham số {transaction} để tham gia đúng transaction đó.
Bỏ tham số có thể làm một bản ghi commit riêng trong khi phần còn lại rollback.
Foreign key sai phải rollback cả tài khoản vừa tạo; integration test có kiểm tra.
Xóa nhân viên ở API hiện là vô hiệu hóa, giữ lịch sử, giống hành vi HRM trước refactor.

6. AUTHENTICATION, AUTHORIZATION VÀ OWNERSHIP
===========================================

Authorization: người đó được làm gì?

Ownership / trạng thái bản ghi:

  Người khác không được hủy đơn của bạn.
  Quản lý không tự duyệt đơn của mình.
  Đơn đã xử lý không được duyệt lần hai.
Các điều kiện này nằm trong read repository / command nghiệp vụ, không chỉ ẩn nút trên UI.

7. PHP ĐỒNG BỘ VÀ JAVASCRIPT ASYNC: PHẦN BẠN CẦN CHÚ Ý NHẤT
===========================================================
PHP quen thuộc:
  $employee = Employee::find($id);

Node:
  const employee = await Employee.findByPk(id);

findByPk trả Promise. await chờ Promise settle và nhường thời gian chờ I/O
cho Node xử lý việc khác; không có nghĩa CPU nặng tự chạy ở thread riêng.

Ví dụ trong controller:
  export const list = async (req, res) => {
    const result = await queryBus.ask(new GetEmployeeListQuery(req.query));
    return data(res, result);
  };

async làm hàm trả Promise. Thiếu await có thể làm result là Promise thay vì dữ liệu.
Error trong Promise cần được await/return để đi đúng luồng xử lý lỗi.
Express 5 chuyển rejection của async route handler về error middleware.
Không viết response lần hai sau khi đã gửi 204 hoặc JSON.

Một số cú pháp quen nhau:
  $user->name             → user.name
  $request->input('name')  → req.body.name
  $request->route('id')    → req.params.id
  $request->query('page')  → req.query.page
  foreach ($items as $x)   → for (const x of items)
  ['name' => 'An']         → {name: 'An'}
  $value ?? 'default'      → value ?? 'default'
  use Namespace\Class    → import {Class} from './file.js'

Trong ESM của project, import relative phải đúng đường dẫn và có .js.
Import là khai báo phụ thuộc file; Express không tự tìm namespace/autoload theo PSR-4.

8. VIEW WEB, JSON VÀ BLADE/EJS
==============================
Laravel:
  return view('employees.index', ['items' => $items]);
  {{ $employee->name }}
  @foreach($items as $employee) ... @endforeach

Node:
  res.render('employees', {result});
  <%= e.user.name %>
  <% for (const e of result.items) { %> ... <% } %>

<%= ... %> escape dữ liệu hiển thị, gần với {{ ... }} của Blade.
<%- ... %> render raw: chỉ dùng cho include/markup đã tin cậy, không cho dữ liệu tùy ý.
src/views vẫn là thư mục view thật. Giao diện xanh dương không đổi trong lần này.

Trang /employees/list trả HTML; /api/employees/list trả JSON.
JavaScript ở public/js/app.js đọc form và gọi API create/update/delete riêng.
JSON dùng cho cả website và mobile; nó không giới hạn ở ứng dụng nhắn tin/mobile.

9. QUEUE, QUEUE BACKEND, EVENT, OBSERVER VÀ SCHEDULER
==================================================
Laravel dispatch(Job)      → BullMQ Queue.add(...)
Laravel queue driver Redis→ Redis queue backend
Laravel queue:work/Horizon→ Notification worker riêng (không phải Express tự gửi mail)
Laravel schedule:work     → npm run schedule, process Node riêng
Laravel Event             → event nội bộ + outbox event
Laravel Observer          → Sequelize afterCreate/afterUpdate/afterDestroy hook

File đọc theo thứ tự:
  src/modules/employees/commands/EmployeeCommands.js
  src/events/index.js
  src/modules/core/models/Outbox.js
  src/queue/index.js
  src/scheduler.js
  services/notifications/src/server.js

User + employee + audit + outbox được ghi cùng transaction.
Sau commit mới phát realtime và xóa cache. Relay đọc outbox và thêm job vào Redis.
Notification service nhận job rồi gửi mail bằng Nodemailer vào Mailpit.
Redis ngừng thì sự kiện pending vẫn còn trong MySQL để relay thử tiếp.

Event và Observer khác nhau:
- Event diễn đạt hành động như employee.created / leave.decided.
- Observer nghe vòng đời ORM và ghi audit tự động.
- Queue là cơ chế xử lý nền; Redis là nơi giữ queue; worker là process thực thi job.
- Scheduler quyết định lúc nào chạy relay/digest, không phải worker.

Lịch hiện có: relay mỗi 10 giây; HR digest 08:00 thứ Hai–Sáu, giờ Việt Nam.
Có CLI chạy thử ngay. SMTP là at-least-once, không cam kết exactly-once khi crash
đúng lúc gửi xong nhưng chưa ghi sent; eventId/Message-ID giúp nhận diện và hạn chế trùng.

10. CACHE, REALTIME VÀ MICROSERVICE
==================================
Cache::remember()          → cached() trong src/lib/redis.js
Cache::forget()            → invalidate() sau mutation
Reverb/broadcast          → Socket.IO trong src/server.js và public/js/realtime.js

Dashboard dùng Redis cache 30 giây và xóa cache khi nghiệp vụ thay đổi.
Redis cache lỗi thì loader vẫn đọc MySQL. Header X-Cache cho biết HIT/MISS/BYPASS.
Socket phải đăng nhập, manager room khác user room; payload không chứa hồ sơ/lương.
Realtime báo có dữ liệu mới, không tự reload form đang nhập của bạn.

Notification service có process, package.json, migration, DB và DB user riêng.
HRM core đọc thông báo qua HTTP nội bộ có service key.
Tách module trong một app không tự động biến thành microservice:
chỉ notification là service tách riêng trong kiến trúc hiện tại.

15. KHI TỰ THÊM MỘT CHỨC NĂNG SAU NÀY
======================================
Ví dụ một thao tác mới thuộc nhân viên:
  1) Xác định module employees sở hữu nghiệp vụ.
  2) Input mới → thêm schema trong requests/EmployeeRequest.js.
  3) Chỉ đọc → Query + ReadRepository; thay đổi dữ liệu → Command Handler.
  4) Thêm Policy action tương ứng nếu có quyền mới.
  5) Controller gửi Query/Command, không nhét SQL vào đó.
  6) Khai báo URL riêng và HTTP method trong routes/api.js hoặc routes/web.js.
  7) Đăng ký Query/Command Handler mới trong HrmServiceProvider.
  8) Thêm migration nếu schema thực sự thay đổi.
  9) Viết regression test, cập nhật tài liệu và chạy lại chức năng liên quan.

Đừng tạo module mới chỉ vì bạn tạo một file mới. Module bám theo nghiệp vụ;
controller, request, query, command và model là các vai trò bên trong module đó.
