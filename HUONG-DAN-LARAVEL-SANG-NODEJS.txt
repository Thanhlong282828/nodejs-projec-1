01 — Biến, const/let và truy cập dữ liệu
==============================================================================

PHP / LARAVEL:
  $name = 'An';
  $user = ['name' => 'An'];
  echo $user['name'];
  echo $employee->id;

NODE.JS / JAVASCRIPT (ORM: SEQUELIZE KHI CÓ QUERY):
  let name = 'An';
  const user = { name: 'An' };
  console.log(user.name);
  console.log(employee.id);

GIẢI THÍCH:
PHP associative array gần JS object; PHP object truy cập bằng ->, JS dùng dấu chấm. JS array là danh sách, không phải một dạng object dùng thay mọi associative array.

ĐIỂM DỄ SAI:
const không cho gán lại binding nhưng user.name vẫn sửa được. Chỉ freeze khi thực sự cần, và Object.freeze là shallow.

CÂU PHỎNG VẤN:
const user có nghĩa mọi dữ liệu bên trong user đều bất biến không?

BÀI TỰ LÀM — CHƯA XEM AI GIẢI:
Viết object employee có code, name và danh sách skills; đổi name rồi giải thích vì sao const không báo lỗi.

02 — So sánh chặt và giá trị rỗng
==============================================================================

PHP / LARAVEL:
  $id = '10';
  var_dump($id === 10); // false
  var_dump((bool) '0'); // false
  $name = $input['name'] ?? 'Chưa có';

NODE.JS / JAVASCRIPT (ORM: SEQUELIZE KHI CÓ QUERY):
  const id = '10';
  console.log(id === 10); // false
  console.log(Boolean('0')); // true
  const name = input.name ?? 'Chưa có';

GIẢI THÍCH:
Dùng === để kiểm tra cả giá trị và kiểu. ?? chỉ thay khi null/undefined, không thay mọi falsy value.

ĐIỂM DỄ SAI:
JS có undefined; chuỗi "0", [] và {} đều truthy trong JS. Không bê quy tắc empty() của PHP sang JS. Number("") là 0, nên cần validation trước khi coi input là ID.

CÂU PHỎNG VẤN:
Vì sao req.params.id thường là string và không nên so trực tiếp với số bằng ===?

BÀI TỰ LÀM — CHƯA XEM AI GIẢI:
Giải thích sự khác nhau giữa value || 10 và value ?? 10 khi value=0.

03 — Function, arrow function và callback
==============================================================================

PHP / LARAVEL:
  function add(int $a, int $b): int {
      return $a + $b;
  }
  $double = fn ($n) => $n * 2;

Arrow function dùng lexical this; không coi arrow và function thường giống hệt nhau trong mọi tình huống. Route cần truyền handler, không gọi handler ngay khi khai báo.

04 — Collection/map/filter/reduce và sort
==============================================================================

PHP / LARAVEL:
  $active = collect($employees)
      ->filter(fn ($e) => $e['active'])
      ->values()->all();
  $names = array_map(fn ($e) => $e['name'], $active);
  $total = array_reduce($items,
      fn ($sum, $i) => $sum + $i['stock'], 0);

NODE.JS / JAVASCRIPT (ORM: SEQUELIZE KHI CÓ QUERY):
  const active = employees.filter(e => e.active);
  const names = active.map(e => e.name);
  const total = items.reduce((sum, i) => sum + i.stock, 0);
  const byId = [...employees].sort((a, b) => a.id - b.id);

GIẢI THÍCH:
filter chọn phần tử; map biến đổi; reduce gom thành một kết quả. Các hàm này xử lý dữ liệu đã có trong RAM.

ĐIỂM DỄ SAI:
Array.map không phải Sequelize query. sort() sửa mảng tại chỗ, và sort mặc định so theo chuỗi; dùng comparator số khi sắp xếp số. reduce cần initial value để xử lý mảng rỗng.

CÂU PHỎNG VẤN:
User.findAll({where}) khác users.filter(...) về nơi xử lý và dữ liệu phải tải thế nào?

BÀI TỰ LÀM — CHƯA XEM AI GIẢI:
Cho 5 sản phẩm, tìm tổng stock và sản phẩm giá cao nhất; phải xử lý cả danh sách rỗng.

06 — Promise và await: khác biệt phải hiểu
==============================================================================

PHP / LARAVEL:
  $user = User::find($id);
  // Theo mô hình Laravel/PHP thông thường,
  // lệnh tiếp theo nhận model hoặc null sau khi query xong.

NODE.JS / JAVASCRIPT (ORM: SEQUELIZE KHI CÓ QUERY):
  const pending = User.findByPk(id); // Promise
  const user = await pending;       // Model instance hoặc null

GIẢI THÍCH:
Promise đại diện kết quả chưa hoàn tất; async function luôn trả Promise. await lấy kết quả khi Promise hoàn tất hoặc ném lỗi khi reject.

ĐIỂM DỄ SAI:
Thiếu await thì biến là Promise, không phải bản ghi. await không biến tác vụ CPU nặng thành tác vụ chạy song song. Node vẫn có thể bị block bởi vòng lặp CPU lớn.

CÂU PHỎNG VẤN:

BÀI TỰ LÀM — CHƯA XEM AI GIẢI:

07 — Chờ tuần tự và chờ nhiều I/O độc lập
==============================================================================

PHP / LARAVEL:

08 — try/catch và lỗi async
==============================================================================

PHP / LARAVEL:
  try {
      $user = User::findOrFail($id);
  } catch (Throwable $error) {
      report($error);
      throw $error;
  }

NODE.JS / JAVASCRIPT (ORM: SEQUELIZE KHI CÓ QUERY):
  try {
    const user = await User.findByPk(id);
    if (!user) throw new HttpError(404, 'Không tìm thấy user');
  } catch (error) {
    throw error; // hoặc xử lý có chủ đích, không nuốt lỗi
  }

GIẢI THÍCH:
try/catch bắt rejection của Promise được await trong block. Express 5 chuyển lỗi/rejection của async handler về error middleware.

ĐIỂM DỄ SAI:
Không catch rồi trả 200 giả, không bỏ Promise chạy ngoài luồng mà không xử lý rejection. Không đưa password, SQL hoặc stack nội bộ ra client.

CÂU PHỎNG VẤN:

09 — Eloquent và Sequelize nằm ở đâu?
==============================================================================

PHP / LARAVEL:
  use Illuminate\Database\Eloquent\Model;
  class Employee extends Model {
      protected $table = 'employees';
  }

NODE.JS / JAVASCRIPT (ORM: SEQUELIZE KHI CÓ QUERY):
  import { DataTypes } from 'sequelize';
  export const Employee = db.define('Employee', {
    code: DataTypes.STRING(30),
    status: DataTypes.ENUM('active', 'inactive'),
  }, { tableName: 'hrm_employees', timestamps: true });

GIẢI THÍCH:
Eloquent và Sequelize đều là ORM: model giúp diễn đạt truy vấn và ánh xạ bản ghi DB thành object. Node.js là runtime, Express là framework HTTP, Sequelize mới là ORM trong HRM này.

ĐIỂM DỄ SAI:
Không gọi Node.js là ORM. ORM không thay thế SQL fundamentals, FK, index, transaction hoặc kiểm tra quyền. Snippet model này rút gọn; model thật có nhiều field hơn.

CÂU PHỎNG VẤN:
Nếu interviewer hỏi "Node có Eloquent không?", bạn trả lời thế nào cho đúng?

BÀI TỰ LÀM — CHƯA XEM AI GIẢI:
Mở src/modules/employees/models/Employee.js và chỉ ra model name, table name, khóa chính.

15 — orWhere ↔ Op.or
==============================================================================

PHP / LARAVEL:
  $users = User::where(function ($q) use ($term) {
      $q->where('name', 'like', "%{$term}%")
        ->orWhere('email', 'like', "%{$term}%");
  })->get();

NODE.JS / JAVASCRIPT (ORM: SEQUELIZE KHI CÓ QUERY):
  import { Op } from 'sequelize';
  const users = await User.findAll({ where: {
    [Op.or]: [
      { name: { [Op.like]: `%${term}%` } },
      { email: { [Op.like]: `%${term}%` } },
    ],
  } });

GIẢI THÍCH:
Cần nhóm OR rõ ràng để khi ghép với điều kiện quyền/scope vẫn giữ đúng logic. Cú pháp [Op.or] là computed property dùng Symbol trong Sequelize.

ĐIỂM DỄ SAI:
Không ghép raw SQL bằng chuỗi input. ORM binding giảm injection cho values nhưng vẫn phải allowlist cột sort/field động nếu cho client chọn. LIKE còn phụ thuộc collation và ký tự wildcard.

CÂU PHỎNG VẤN:
Vì sao (company=A AND name LIKE x) OR email LIKE x có thể sai quyền dữ liệu?

BÀI TỰ LÀM — CHƯA XEM AI GIẢI:

35 — Auth/password/token
==============================================================================

PHP / LARAVEL:
  $hash = Hash::make($password);
  $ok = Hash::check($password, $user->password);
  // Laravel auth guard tùy cấu hình session/token.

NODE.JS / JAVASCRIPT (ORM: SEQUELIZE KHI CÓ QUERY):
  const hash = await bcrypt.hash(password, 12);
  const ok = await bcrypt.compare(password, user.password);
  // HRM ký JWT, gửi cookie HttpOnly hoặc nhận Bearer token.

GIẢI THÍCH:
Hash là một chiều để kiểm tra mật khẩu, không phải mã hóa có thể giải mã. Token đại diện phiên/quyền xác thực, không phải password.

ĐIỂM DỄ SAI:
Không dùng SHA256 trực tiếp thay password hashing; không nhận role từ client làm bằng chứng quyền. JWT payload không mặc định mã hóa, cần kiểm tra chữ ký/hạn/issuer/audience.

37 — Observer và Event
==============================================================================

  Employee.addHook('afterCreate', 'audit', async (record, options) => {

38 — Queue/Redis/Worker/Scheduler
